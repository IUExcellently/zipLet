# 递归解压归档设计

## Context

当前 Python 入口是示例脚本。任务可能包含多条嵌套分支，磁盘峰值受最大的在途任务影响。变更动机见 proposal.md。

## Goals / Non-Goals

- 为本地批处理提供独立任务、可复用密码记录和安全发布边界。
- 首版范围为单机执行及完整归档文件。分卷与自解压样本留待单独验证。

## Decisions

1. **使用官方 7-Zip CLI。** 一个引擎可覆盖目标格式，减少分别维护格式库的成本。实现时用本机样本验证 RAR、加密归档、WIM 及伪装后缀。配置使用 `ZIPLET_INPUT_DIR`、`ZIPLET_OUTPUT_DIR`、`ZIPLET_PASSWORD_FILE` 和 `ZIPLET_MAX_WORKERS`。
2. **按内容探测并确认。** 先探测归档签名，再由引擎确认类型和成员。识别 ZIP 内的 Office 内容类型与部件结构。每层先验证成员路径及类型，拒绝绝对路径、越界路径和链接。引擎调用使用参数列表、非交互及超时，普通日志过滤命令参数和工具输出中的密码。
3. **按外层任务调度。** 外层任务由有限线程池调度，同一任务按深度优先遍历全部子归档。默认单线程。相比在每层派生并行任务，这给共享卷的空间预留和结果清理提供了明确的任务边界。
4. **持久化密码命中。** 用 SQLite 保存归档内容指纹、任务内相对路径、层级、状态及候选标识。候选标识由本地密钥计算，重跑从当前候选集匹配。失败尝试使用独立暂存目录并清除当次不完整输出。引擎无法区分密码错误与损坏时，单独记录验证未通过且原因未决。
5. **分阶段发布。** 工作区在输出卷上，独立于扫描树。图片与视频通过内容识别及解析器读取校验。每个源包有独立输出目录，按源相对路径及文件名区分，保留媒体的相对结构，遇到重名时显式报告。校验成功后在同卷提交暂存目录，再依据工作清单清理中间包。记录发布及清理阶段，中断重跑时先核对已有输出，支持继续未完成的清理。

## Risks / Trade-offs

- 所有中间包保留到任务成功，单链仍可能超出可用空间。进入每层前按可得的展开大小检查并预留空间，实际写入遇到磁盘耗尽时停止该任务并记录进度。
- 加密归档头可能让成员清单只能在密码命中后读取。每次成功读取清单后先校验成员和空间，再允许写入。
- 媒体解析属于可读性校验。首版检查图片可解码、视频容器与视频流可解析。视频全帧解码会显著增加批量处理时间。
